# Convention: a superseding convention doc retires or supersession-marks the doc it replaces in the same change

**Rule.** When a drift reconciliation (or any rule change) lands a convention doc that supersedes an existing one, the same change must also handle the superseded doc: either retire it or stamp it with an explicit supersession banner ("Superseded by <new-doc> on <date> — do not apply") at the top. A workspace state where two live convention docs assert opposite operative rules is itself a defect, regardless of which one is newer.

**Grounding.**
- `suggested/agent-updates/model-command-runtime-scoped-supersedes-grok-only.md`: "The earlier reading — '`/model` only switches Grok models' — is superseded ... and must not be reasserted in docs, skills, or review comments", and explicitly: "Leaving both readings live is worse than either alone: a reviewer enforcing Grok-only would reject correct runtime-scoped catalog code."
- The workspace currently exhibits the failure: `suggested/agent-updates/model-command-is-grok-only.md` still states its rule with no supersession marker, alongside its superseder. The same pair exists for `detect-only-runtime-state.md` ("Claude is currently in this state") versus the shipped Claude catalog harness in `docs/LOCAL_CLI_AUTH.md`.
- Existing law covers the adjacent steps but not this one: "a drift reconciliation is finished only when the canonical value is written into a convention doc" creates the new doc; "reconciliation scrubs operative references but preserves historical decision records" scrubs quotes elsewhere — neither names the old convention doc itself as a mandatory scrub target.

**Why:** convention docs are the enforcement surface reviewers and agents actually load. Unlike a stale sentence in a wiki page, a stale convention doc actively instructs someone to reject correct code or reassert the dead value in new docs — it is an operative rule, not a record. Because both docs look equally authoritative to a reader who finds only one, timestamps alone do not resolve the conflict; only an in-file marker or removal does. Same-change coupling (the workspace's general coupling law applied here) is what keeps the window of dual-rule ambiguity at zero.

**How to apply:** when authoring a convention doc whose Rule contradicts an existing convention doc, treat the old doc as part of your change surface: add the supersession banner (preserving the body as a historical decision record, per the scrub convention) or retire it via the phantom-grounded-doc repair skill. When reviewing a reconciliation, a diff that adds the new convention doc without touching the superseded one is incomplete. When sweeping, grep convention docs for rules contradicting a newer doc's "superseded" claim — each hit is an unfinished reconciliation.
