# Convention: live-behavior doc sections carry a '(shipped)' marker — marked claims outrank unmarked and older statements in drift adjudication

**Rule.** When a doc describes behavior that actually exists in the running product, the section is explicitly marked **"(shipped)"** — e.g. `docs/LOCAL_CLI_AUTH.md`'s "TUI usage (shipped)" table. The marker is operative, not decorative: in a drift adjudication, a claim inside a shipped-marked section is treated as a report of live behavior and outranks (a) unmarked prose in the same or other docs, (b) statements lifted from earlier revisions, and (c) convention docs whose grounding quotes predate the marked section. Conversely, a section describing planned or aspirational behavior must **not** carry the marker — mislabeling a design intention as shipped manufactures false evidence.

**Grounding.**
- `docs/LOCAL_CLI_AUTH.md` titles its command table "TUI usage (shipped)" — the marker distinguishes the live command surface from the design rationale ("Why a warm connection") in the same file.
- `suggested/agent-updates/model-command-runtime-scoped-supersedes-grok-only.md`, Grounding: "this section of `docs/LOCAL_CLI_AUTH.md` is explicitly marked '(shipped)', and for live services on-wire/shipped behavior is canonical over older doc statements."
- `suggested/workflows/reconcile-model-scope-drift.md` uses the same lever: Value B is quoted from "'TUI usage (shipped)' (modified *after* the convention doc)" and prevails over the convention doc's older quote.

**Why:** the workspace's evidence hierarchy already says on-wire behavior is canonical for live services, but adjudicators cannot always probe the wire — the /model-scope reconciliation was settled largely on the strength of the "(shipped)" annotation plus timestamps. The marker is the doc-side proxy for on-wire evidence: it records that someone asserted "this is what the product does today," not "this is what we intend." Without the convention, the marker is invisible — a future editor could add or drop it casually, silently changing the evidentiary weight of every claim in the section.

**How to apply:** when documenting a feature that has landed, put it under a "(shipped)" heading (or move it there when it lands); keep design intent in unmarked sections. When adjudicating a drift, check whether either competing value sits inside a shipped-marked section — if exactly one does, that value presumptively wins pending an on-wire probe. When reviewing a doc change, treat adding "(shipped)" to unlanded behavior, or removing it from live behavior, as a defect on par with editing a frozen drift fact.
