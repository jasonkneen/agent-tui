# Convention: /model is runtime-scoped — it switches the active vendor's catalog; the Grok-only reading is superseded

**Rule.** `/model` operates on the **active runtime's** model catalog, not on a fixed Grok list. After `/runtime codex` or `/runtime claude`, Agent TUI loads that vendor's catalog and `/model` switches within it; the choice persists as a vendor-scoped key in `~/.agent-tui/runtime.toml` (`codex_model` / `claude_model`). The earlier reading — "`/model` only switches Grok models" — is superseded by the newer shipped behavior and must not be reasserted in docs, skills, or review comments. Vendor selection itself still belongs exclusively to `/runtime` (aliases `/provider`, `/rt`): `/model` never changes which vendor serves turns, only which model within the already-selected vendor.

**Grounding.**
- `docs/LOCAL_CLI_AUTH.md` (2026-07-16 revision), "TUI usage (shipped)": "After `/runtime codex` or `/runtime claude`, Agent TUI loads that vendor's model catalog and **`/model` switches it**. Selection is stored in `~/.agent-tui/runtime.toml` (`codex_model` / `claude_model`)."
- Same table: catalog sources are per-vendor — "**Codex** — `model/list` over warm app-server" and "**Claude** — Claude Code Agent SDK harness via `claude -p --output-format json` (+ sticky `--resume`)" — i.e. the catalog `/model` shows is whatever the active runtime serves, which is incompatible with a Grok-only scope.
- The workspace's drift rules: this section of `docs/LOCAL_CLI_AUTH.md` is explicitly marked "(shipped)", and for live services on-wire/shipped behavior is canonical over older doc statements. The older Grok-only sentence and the convention doc quoting it describe a prior state.

**Why:** the /model-scope drift (Grok-only vs runtime-scoped catalog) has a registered reconciliation workflow, and a drift reconciliation is finished only when the canonical value lands in a convention doc — this is that doc. Leaving both readings live is worse than either alone: a reviewer enforcing Grok-only would reject correct runtime-scoped catalog code, and a support answer quoting "working as designed — /model doesn't show Claude models" is now simply wrong once `/runtime claude` is active. Note what did *not* change: the hard boundary that vendors never ride the Grok sampler path is untouched, because `/model` still cannot select a vendor — the catalog it browses is determined entirely by the `/runtime` choice.

**How to apply:** when writing or updating docs and skills that mention `/model`, state its scope as "the active runtime's catalog" and name the vendor-scoped `runtime.toml` keys as the persistence location. Sweep operative surfaces (the switch-runtime skill, `AGENTS.md` runtime notes, user-guide text) for the superseded "Grok models only" phrasing and update them, preserving historical decision records per the reconciliation-scrub convention. When reviewing a change to the `/model` handler, verify it reads the catalog from the active runtime (live-fetched, never hardcoded) and writes the selection to the correct vendor-scoped key — and still refuses to change the vendor itself.
