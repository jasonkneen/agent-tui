# Audit failure-family catalogs against their instance artifacts (bidirectional)

The family-cataloging skill defines the genre as "a lookup-genre index derived from the instance artifacts, never the other way around" (`suggested/skills/catalog-failure-family.md`), and the index-doc law says derivation "is also what makes the bidirectional index audits meaningful" — but it names audits only for lifecycle maps and routing tables (`suggested/agent-updates/all-index-docs-are-derived.md`). Failure-family catalogs are the third index genre member with none, the same gap the routing-table audit was authored to close for its genre. And the catalogs carry pointer cells of their own: the phantom-reference family's instance table maps each pointer surface to "Detected by" and an "Owning fix artifact" (`suggested/docs/phantom-reference-failure-family.md`) — cells that can themselves go phantom.

Record: the failure-family catalog docs. Reality: the instance artifacts they cite and the workspace's live defenses.

## Phase 1: Enumerate from reality

Glob `suggested/docs/` for catalogs self-described as a family's "index" with a shared-anatomy section and an instance catalog (today: the apparent-blessing, phantom-reference, and invisible-removal families — illustrative snapshot; the glob is the instruction). Separately enumerate the workspace's conventions, skills, and workflows.

## Phase 2: Catalogs → reality

For every cataloged instance in every family doc:

- **Cited path resolves** — a dead path is a phantom instance pointer, an instance of the very family one of these catalogs names.
- **The artifact still names the failure in its own words** — a reworded or lightened artifact that no longer defends against the family's anatomy is a stale instance.
- **Independence still holds** — re-run the independence check on the cataloged sources; a later edit that made one instance quote another collapses two instances into one and may drop the family below the convergence threshold.
- **The paired counter-design still exists** — each instance is cataloged "with the counter-design it already has"; a retired counter-design is an undefended instance, not a formatting problem.

## Phase 3: Reality → catalogs

- Every artifact whose defect "fits the anatomy" of a named family is cataloged there — the anatomy is predictive, so an uncataloged match is a missing instance, not a new family.
- Multiple independent artifacts defending against a failure no catalog names is a candidate new family — route to `suggested/skills/catalog-failure-family.md`.

## Phase 4: Reconcile — every mismatch class has an owner

- Phantom or stale instance pointer → repair per the phantom-reference family's shared anatomy (establish what happened to the artifact, then re-point, re-quote, or retire after a survivor sweep).
- Missing instance → add it to the catalog, derived from the artifact (fixes land in the artifacts first; the catalog is derived).
- Collapsed independence → downgrade or merge instances; if the family falls below threshold, the catalog itself is a convergence claim that no longer holds.
- Candidate new family → author via the cataloging skill; do not grow an existing family to absorb it.

This sweep registers in the standing-audit registry in the same change it lands, and must pass the registry-conformance check (both directions, enumeration from reality, this reconcile phase) at bind time.
